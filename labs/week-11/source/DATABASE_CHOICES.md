# บันทึกการเลือกใช้ฐานข้อมูล (Database Choices)

เอกสารสรุปความเข้าใจจากบทเรียนที่ 8 "ทางเลือกฐานข้อมูล (SQL / NoSQL / async)" สำหรับโปรเจกต์ Campus Service Request

---

### 1. ทำไมโปรเจกต์นี้เลือก SQLite แทน MongoDB?

โปรเจกต์ Campus Service ของเรามีลักษณะข้อมูลที่มีโครงสร้างชัดเจนและตายตัว (Structured Schema) ทุกรายการคำร้องมีฟิลด์ข้อมูลที่แน่นอนเหมือนกัน เช่น รหัสคำร้อง สถานะ และผู้ส่งคำร้อง อีกทั้งข้อมูลมีความสัมพันธ์ระหว่างตารางอย่างชัดเจน (Relational Data) โดยคำร้องต้องเชื่อมโยงไปยังข้อมูลผู้ใช้งานผ่าน Foreign Key 

การเลือกใช้ฐานข้อมูลเชิงสัมพันธ์แบบ SQL อย่าง **SQLite** จึงตอบโจทย์ความถูกต้องของข้อมูลได้ดีที่สุดผ่าน Schema Constraints และการทำ JOIN ตาราง ต่างจาก **NoSQL** อย่าง **MongoDB** ที่เก็บข้อมูลแบบ Document ไร้โครงสร้างตายตัว ซึ่งเหมาะกับข้อมูลที่มีความหลากหลายและเปลี่ยนแปลงฟิลด์บ่อยมากกว่า นอกจากนี้ SQLite ยังเป็นฐานข้อมูลแบบ Serverless ที่ฝังมากับตัว Node.js (`node:sqlite`) ไม่ต้องติดตั้งหรือรันเซิร์ฟเวอร์แยก ทำให้โปรเจกต์เรียบง่ายและดูแลง่ายอย่างมาก

### 2. ถ้าวันหนึ่งต้องเปลี่ยนไป MongoDB จะกระทบชั้นไหนบ้าง?

หากระบบจำเป็นต้องเปลี่ยนจาก SQLite ไปใช้ MongoDB จะส่งผลกระทบต่อ 2 ชั้นในระบบ ได้แก่ **ชั้น `service`** และ **ชั้น `controller`**:

1. **ชั้น Service (กระทบโดยตรง):** ต้องรื้อและเขียนตรรกะการดึงข้อมูลใหม่ทั้งหมด จากเดิมที่เขียนคำสั่ง SQL Query ต้องเปลี่ยนไปใช้คำสั่งและไลบรารีของ MongoDB Client (เช่น Mongoose หรือ `mongodb` driver)
2. **ชั้น Controller (กระทบเพราะการเปลี่ยนสัญญา):** เนื่องจากไลบรารี MongoDB ต้องเชื่อมต่อผ่านเครือข่าย การทำงานจึงเป็นแบบ **Asynchronous** (คืนค่าเป็น Promise) ส่งผลให้ฟังก์ชันในชั้น Service ต้องเปลี่ยนจากฟังก์ชันแบบ Sync ธรรมดาไปเป็นฟังก์ชัน `async` ดังนั้น Controller ซึ่งเป็นผู้เรียกใช้ Service จึงต้องปรับให้รองรับด้วยการใส่ `async` และเติม `await` หน้าคำสั่งเรียก Service เสมอ

*(หมายเหตุ: ส่วนชั้น Frontend จะไม่ได้รับผลกระทบใด ๆ เพราะ REST API Endpoint รูปแบบ Route และโครงสร้าง JSON ที่ส่งกลับไปให้ผู้ใช้ยังคงเหมือนเดิมทุกประการ)*

### 3. async จำเป็นเมื่อไร ไม่จำเป็นเมื่อไร?

* **ไม่จำเป็น (Sync เพียงพอ):** เมื่อฐานข้อมูลทำงานอยู่ภายในกระบวนการและเครื่องเดียวกัน (Local / In-process File) เช่น SQLite ที่เก็บเป็นไฟล์ในเครื่อง การอ่านข้อมูลลงดิสก์ทำได้รวดเร็วระดับเสี้ยววินาทีและไม่ต้องรอสัญญาณข่าย การสั่งงานแบบ Synchronous จึงทำงานเสร็จทันทีโดยไม่ต้องรอ Promise หรือใช้ `await`
* **จำเป็น (ต้องใช้ Async):** เมื่อฐานข้อมูลอยู่คนละเครื่องกับ API Server เช่น Cloud Database อย่าง MongoDB Atlas หรือ PostgreSQL ที่ต้องส่งข้อมูลผ่านเครือข่าย (Network I/O) ซึ่งมีความล่าช้า (Latency) การใช้ **`async` / `await`** มีความจำเป็นอย่างยิ่ง เพื่อให้ Node.js ปล่อยให้ Event Loop ไปรับคำขอของผู้ใช้คนอื่นต่อได้ระหว่างรอผลลัพธ์จากเครือข่าย โดยไม่ทำให้ทั้งระบบค้างหรือบล็อกการทำงาน (Non-blocking I/O)
